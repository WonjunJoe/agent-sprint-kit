# agent-sprint-kit

사람 한 명과 코딩 에이전트(Codex · Claude Code · Cursor)가 **세 시간 안에** 무언가를 만들고, 끝에 사람이 혼자 설명까지 할 때 쓰는 작업 규칙.
결과물이 아니라 **일하는 방식**이다 — 코드나 정답은 들어 있지 않다.

- [`AGENTS.md`](AGENTS.md) — 에이전트가 읽는 규칙. 작업 폴더 맨 위에 두면 Codex 가 알아서 읽는다.
- 이 README — 사람이 보는 순서와 말 모음.

## 쓰는 법

```sh
git clone https://github.com/WonjunJoe/agent-sprint-kit ~/kit
cd <작업 폴더>
[ -f AGENTS.md ] || cp ~/kit/AGENTS.md .   # 이미 있으면 덮지 않는다
codex
```

작업 폴더에 `AGENTS.md` 가 원래 있었다면 첫 말 앞에 「`~/kit/AGENTS.md` 도 읽고 따라」를 붙인다.

## 세 시간

| 경과 | 사람 | 에이전트 |
|---|---|---|
| 0–20분 | 과제 안내를 **직접** 읽는다 · 요구사항을 정하는 사람(업무 담당자 등)에게 묻는다 | 이해 — 요구사항 표 · 제출물 · 모호한 점 |
| 20–35분 | 계획을 읽고 고친다 | `PLAN.md` · 첫 커밋 |
| 35–140분 | 화면 확인 · 다음 단계 고르기 · 방금 만든 코드 읽기 | 단계마다 구현 → 검증 → 커밋 → `WORKLOG.md` 한 줄 |
| 140–160분 | 무엇을 뺄지 정한다 | 새 기능 멈춤 · 전체 검증 · `REPORT.md` |
| 160–170분 | **내 말로** 설명해 본다 | 설명 정리 |
| 170분 | 제출 | — |

- 30분마다 한 번 묻는다: 「지금 제출하면?」
- 에이전트가 도는 동안 사람은 기다리지 않는다 — 다음 질문을 고르고, 방금 만든 코드를 읽고, 화면을 눌러 본다.
- 승인을 묻는 화면은 눌러야 넘어간다. 틈틈이 터미널을 본다.

## 말 모음

| 때 | 말 |
|---|---|
| 시작 | `AGENTS.md 대로 하자. 과제 안내와 파일을 읽고 1단계(이해)만 — 요구사항 표 · 제출물 · 모호한 점(추천 가정 포함). 코드는 아직.` |
| 답을 받으면 | `담당자 답: … 이걸로 가정을 고치고 PLAN.md 를 써.` |
| 만들 때 | `n단계 해.` |
| 막히면 | `멈춰. 원인 가설 셋, 각각 확인할 명령 하나씩. 가장 싼 것부터.` |
| 30분마다 | `지금 제출하면 요구사항 표에서 몇 줄이 충족이야? 증거와 함께.` |
| 끝나기 40분 전 | `새 기능 멈추고 검증 · 기록(4 · 5단계). REPORT.md 써.` |
| 끝나기 20분 전 | `설명해 줘 — 내가 5분 안에 말할 수 있게. 구조 · 흐름 · 결정 셋(왜 · 버린 대안) · 한계, 내가 헷갈릴 만한 곳부터.` |
| 리뷰(선택) | 다른 터미널에서 `/review` 가 있으면 그것, 없으면 `방금 커밋을 요구사항 표에 비춰 리뷰해. 버그 · 빠진 것만.` |
| 대화가 길어지면 | `/new` 뒤 `PLAN.md 와 WORKLOG.md 를 읽고 이어서.` |

## 왜 이렇게

- **기록이 과정을 보여 준다.** 계획 파일 · 작은 커밋 · 테스트 출력 · 협업 기록이 남으면 무엇을 왜 했는지 누구든 따라갈 수 있다.
- **사람이 설명할 수 있어야 끝이다.** 에이전트가 사람의 이해보다 앞서 나가면 그 차이가 빚이다. 그래서 단계마다 세 줄 보고, 끝에 설명 리허설.
- **확인한 것만 됐다고 한다.** 「될 것 같다」와 「테스트가 통과했다」는 다르다.

실제 서비스를 에이전트와 함께 만들며 쓴 `AGENTS.md` 를 세 시간짜리로 줄인 것이다.
